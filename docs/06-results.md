# 06 · 评测结果与验收口径

> 本文档只描述验收口径的设计思路。文中涉及的数值均为**合成演示数据**，用于说明指标定义与判读方式，与任何真实企业经营数据无关。

## 一、验收看什么

编译层验收分三类：结构完整性、编译正确性、检索可用性。三者分别回答「页面全不全」「聚合对不对」「问答能不能召回」。

| 维度 | 指标 | 判定方式 |
|---|---|---|
| 结构完整性 | 四类页面数量、index 覆盖率 | 每类页面都有对应目录与索引条目，无孤立页 |
| 编译正确性 | 多源聚合来源数、双向链接对称性 | 聚合页来源数 ≥ 2；链接相对路径可被 lint 校验 |
| 检索可用性 | 检索探针命中率 | 用固定探针集跑检索，命中即通过，不只看本地重灌语料的测试 |

## 二、lint 巡检口径

- 检查五类：锚定、死链、孤立页、冲突、死循环。
- 关键区分：「待聚合占位」不是死链，必须与真实死链分开计数，否则误报会淹没真问题。
- 基础设施失败（限流、5xx）要与质量失败分开统计，否则门禁会持续误报。

## 三、聚合层回归

- 增量编译：新增源后只重编受影响的页面，其余不动；用「重编页数上限」防止退化成全量重编。
- 多源聚合：概念页必须带来源列表，来源数不足时不得生成聚合结论。
- 权威口径：关键事实只允许一个真相源，且在编译层做确定性覆盖；提示词只提升概率，不保证正确。

## 四、三条方法论结论

1. **测试绿 ≠ 线上对**：验证必须做检索探针或直接查线上索引，不能只看把语料重灌进临时库的测试结果。
2. **护栏要放共享位置**：多入口系统里，护栏必须由所有编译入口 import 复用，只加一处等于没加。
3. **空输入比报错更危险**：聚合源为 0 时模型会输出「原文未提及」的空壳页且能通过字段校验，必须加「有效源数 ≥ 1」前置校验。
