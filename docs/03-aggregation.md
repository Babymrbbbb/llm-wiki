# 03 · 概念聚合：多源合并一页

## 目标

同一实体/概念出现在多篇源文件中时，不再每篇各生成一页（碎片化），而是**合并为一页聚合页**，来源列表逐条列源。

## 实现：aggregation_index.json 聚合索引

聚合索引是概念聚合的核心数据结构：`entity/concept → 源文件列表`。

```json
{
  "entity/金粒门.md": ["竞品动态/2026-07-01.md", "行业趋势/2026-07-10.md", "私域运营/会员体系.md"],
  "concept/会员体系搭建.md": ["私域运营/会员体系.md", "品牌营销/会员储值.md"]
}
```

## 编译流程

1. **LLM 识别**：每次编译一篇源文件，LLM 在输出末尾追加 `AGG` 注释块，声明该源涉及哪些实体/概念。
2. **写入索引**：`build_wiki.py` 解析 `AGG` 块，把源文件路径追加到 `aggregation_index.json` 对应页面。
3. **聚合页生成**：聚合页的「摘要 / 关键事实 / 概念描述」为多源综合描述，每条标注来源。
4. **局部重编**：新源加入后，只重编该聚合页（`--local-rebuild`），不触发全量。

## 效果（真实运行）

| 页面 | 来源数 |
|---|---|
| 品牌实体页 A | 80+ 源 |
| 品牌实体页 B | 45+ 源 |
| 概念页（会员体系） | 多源合并 |

## 边界与占位

- 长尾概念（只被 1 篇引用）不强制聚合，保留为「待聚合占位」——不算死链，后续增量编译按需补生成。
- 聚合冲突（同一事实多源矛盾）写入异常队列，人工裁决，不静默丢弃。

## 提示词要求

每次编译调用在 system prompt 注入：

```
请在输出末尾追加 AGG 注释块，格式：
<!-- AGG: entity/实体A.md, concept/概念B.md -->
声明本页涉及的实体/概念，供聚合索引使用。
```
