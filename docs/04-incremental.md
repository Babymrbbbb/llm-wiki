# 04 · 增量局部重编：--local-rebuild

## 问题

知识库是持续增长的。每次新增几篇资料，如果都全量重编，成本随库大小线性上涨，很快就不可接受。

## 解法：反向闭包局部重编

`--local-rebuild <page>` 只重编**指定页 + 按双向链接反向闭包算出的受影响页**，绝不触发全量重编。

```
用户指定重编页 P
   │
   ▼
1. 读取 P 的「关联页面」段 → 得到直接关联目标 T1, T2...
   │
   ▼
2. 反向闭包：对每个 T，再读 T 的「关联页面」段
   → 若 T 也链回 P（对称），T 纳入重编范围
   → 递归直到闭包收敛（限制层级，防循环依赖）
   │
   ▼
3. 只重编闭包内的页面 + 更新 index.md / log.md
   │
   ▼
4. lint 只巡检受影响页
```

## 命令行

```bash
# 新增测试源后，局部重编受影响页
python build_wiki.py --local-rebuild entity/竞品A.md
```

## 实测结果

新增 1 篇测试源 → 执行 `--local-rebuild 会员体系运营逻辑`：
- 重编 **4 页**（成功 4 / 失败 0）
- 未触发全量重编
- lint 复检通过

## 与 --skip-existing 的配合

| 参数 | 作用 | 场景 |
|---|---|---|
| `--skip-existing` | 已生成页面的源文件跳过 | 全量续跑（增量续传） |
| `--local-rebuild` | 只重编指定页 + 受影响页 | 单页修正 / 新源聚合 |
| `--batch` | 只处理指定批次/子库 | 分批编译 |

## 硬约束

- 只有「推倒重建」步骤允许清空全 wiki
- 增量聚合触发时，`--local-rebuild` 必须限定在受影响页闭包内
- lint 报告必须记录「受影响页重编数」，可追溯
