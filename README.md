# LLM Wiki — raw → wiki → RAG 双轨知识编译层（自研方法论）

> 一套真实运行过的 **LLM 知识库编译方法体系**：把 1,600+ 篇原始资料自动编译为可导航的 wiki 知识层（实体 / 概念 / 对比 / 综合四类页面），实现**同一概念多源聚合、页面间双向链接、增量局部重编、lint 全库巡检**。
>
> **说明**：本仓库公开的是**通用化、脱敏后的方法论**（架构思路 + 编译契约 + 聚合/增量/lint 设计）。原体系在某连锁零售品牌知识库真实运行（1,641 篇 → 1,317 页，lint 锚定 100%），但**生产实现深度绑定品牌私有知识库与内部模型服务，属于品牌独特自研改造，不对外提供可运行源码**。

> 📌 **技术关键词**：RAG 知识库 / 概念聚合 / 双向链接 / 增量编译 / Schema 契约 / lint 巡检 —— 覆盖企业知识库工程化的完整落地路径。

## 为什么做这个

RAG 直接喂原始文档有两个真实问题：

1. **原始资料保真但不可导航**：1,600 篇散落的 markdown，人工检索靠文件名猜，RAG 召回靠关键词碰运气，同一主题分散在几十篇里。
2. **泛词塌缩**：垂直领域的高频词（如「会员」「复购」「短保」）被大量文档引用，关键词检索被泛词淹没，精确信息反而排不上来。

解决方案不是只换检索算法，而是加一层**编译层**：把原始资料离线编译成可导航的 wiki 知识层，人工检索与 RAG **共用同一编译产物**——这就是 raw → wiki → RAG 双轨架构。

## 核心概念速览

| 概念 | 一句话 |
|---|---|
| **raw 层** | 原始资料只读不可变，保真兜底（1,641 篇） |
| **wiki 层** | 编译产物可导航：entity 实体 / concept 概念 / comparison 对比 / synthesis 综合 |
| **Schema 契约** | `wiki_schema.md` 每次编译注入 LLM 提示词，保证行为一致 |
| **概念聚合** | 同一实体/概念多源 → 合并一页，来源列表逐条列源（聚合页 80+ 源） |
| **双向链接** | entity ↔ concept ↔ synthesis 层级互链，comparison 挂接两端实体 |
| **增量重编** | `--local-rebuild <page>` 按双向链接反向闭包只重编受影响页，实测仅 4 页 |
| **lint 巡检** | 锚定 / 死链 / 孤立页 / 冲突 / 死循环五类检查，锚定通过率 100% |

## 方法论核心

```mermaid
flowchart TD
    A[新资料入库 或 推倒重建全量] --> B[build_wiki 读取 raw 文件]
    B --> C[剥离水印 生成 summary 草稿]
    C --> D[概念聚合: LLM 识别 entity/concept 写入 aggregation_index]
    D --> E[自动化聚合: 高频概念自动生成聚合页]
    E --> F[跨页联动: 更新关联页面 双向链接]
    F --> G[lint 全量巡检: 锚定/死链/孤立页/冲突/死循环]
    G -->|异常| H[异常队列 → 人工裁决]
    G -->|通过| I[wiki 层可导航 供 RAG 与人工共用]
```

> 命令行示例（`--batch` / `--local-rebuild` 等）为方法论示意，生产实现依赖品牌私有知识库与内部模型服务，不提供可运行源码。

## 这是一套体系的一部分，不是孤立项目

> **核心**：所有仓库围绕同一件事——让 45 家门店的真实业务被 AI 高效落地。每个仓库解决一个环节，合起来是一条完整生产线。


### 本仓库在体系中的位置

**为什么改造**：kb-cli 解决了「原始资料找得到」，但 1,600+ 篇原始资料**不可导航**——人工靠文件名猜、RAG 泛词塌缩、同一主题散落几十篇。不改，知识库越大越难用。

**意义**：在 kb-cli 之上加一层**知识编译层**——raw → wiki → RAG 双轨：原始资料保真不可变，编译产物可导航聚合（实体/概念/对比/综合四类页），人工与 RAG 共用同一产物，精确召回大幅提升。

**结合哪些部分**：
- 检索底座是 **kb-cli**（分层 + 召回优先）
- 编译过程跑在 **sensenova-gateway** 的稳定模型通道上
- 自动化聚合由 **ai-native-team** 的知识库每日维护任务驱动
- 编译产物被 **驾驶舱** 的 AI 结论卡引用

**单独用的价值**：即使不用整套体系，任何「原始资料上千篇、检索被泛词淹没」的团队都能直接复用这套方法论——概念聚合 + 增量局部重编 + lint 质量门，把原始文档变成可导航知识层。
